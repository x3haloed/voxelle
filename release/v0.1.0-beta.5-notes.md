# Voxelle 0.1.0 beta 5

> This local candidate was superseded before publication. A current RustSec
> scan found patched dependency releases needed for the next candidate; no
> second manifest was signed under sequence 5.

This release candidate binds the current human and agent experience to one
reviewed source generation. People and residents share the same spaces,
ordinary messages, flat threads, exact reply relationships, permissions,
retention, synchronization, and Rust-owned semantic commands.

Agent coordination now has durable owner-bound observation cursors,
device-certified origin provenance, idempotent sends, explicit observation and
handled-result assertions, bounded continuation leases, causal actionability,
origin-directed review hints, and owner-local attention that remains distinct
from principal-level disposition. Human, Alpha, and Beta can continue one
readable thread through delegation, decline, result binding, disconnect, crash,
and restart without introducing an agent-only task authority.

Human-facing changes retain goal-first setup and invitation, explicit recovery
paths, draft-safe customization, focused review for consequential actions,
peer-specific connection recovery, and direct-media degraded states. Buttons,
keyboard shortcuts, the command palette, native automation, and the inhabitant
surface continue through the same semantic vocabulary and admission path.

The universal macOS DMG and Windows x86-64 NSIS installer remain unsigned by
Apple- or Microsoft-recognized publishers. Authenticate their exact bytes with
`VOXELLE-RELEASE.json` and follow the narrow instructions in
[`docs/INSTALL_UNSIGNED.md`](https://github.com/x3haloed/voxelle/blob/v0.1.0-beta.5/docs/INSTALL_UNSIGNED.md).

Native Windows launch, physical non-loopback multi-peer networking, actual
assistive-technology and media-device operation, public release readback, and
offline signing-key custody remain release-receipt gates. This candidate and
its local verification do not claim those observations.

  `eb2e2d017a2cee6198149d678349829ce33521c72ea1247d4a167772aea22a5a`;
- Windows x86-64 NSIS installer SHA-256
  `edaa87d5579fde214f148e1bb67063bacbe4c463802f7e73be6f900c776161f9`;
- signed product update SHA-256
  `a08f5bfac89e79f234e664bd54dcf7978f0a71a6ac6e0cb85d743298231c7eb9`.

The release verifier authenticated all three bytes against signer
`ed25519:sT3IfAZVI-Vm_Qoa7I2GOqK2yFBI6AdoNAUceYy8lrw`. `hdiutil` verified the
DMG, `lipo` reported both `x86_64` and `arm64`, and strict deep code-sign
verification accepted the ad-hoc hardened-runtime application. The packaged
Windows application is PE32+ x86-64 GUI code; the NSIS launcher uses NSIS's
32-bit GUI stub. No native Windows installation or launch was inferred from
that cross-build inspection.

The Windows cross-bundler warned that Tauri's bundle-type marker was absent.
Voxelle does not include or configure Tauri's updater plugin: signed product
generation verification, staging, activation, and rollback use Voxelle's Rust
update manager and `.voxupdate` format. The marker therefore does not affect
this candidate's product-generation update path. It would need renewed review
if native executable self-update through Tauri were introduced.

The generated beta evidence template passes release identity and deliberately
fails closed for distribution, native Windows, physical field, lived human,
and signing-custody sections. A packaged macOS launch and live
beta.4-to-beta.5 activation/rollback/reactivation rehearsal remains pending and
must be observed before recording the packaged distribution attestations.
